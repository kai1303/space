# Channel Files browser

The user approved building the Slack-inspired file browsing described in the UI review, with confirmation by tests. A Files entry in channel navigation opens Space's existing right-side panel style. It sits beside the conversation on wide screens and replaces the conversation area on small screens. Opening thread/search closes Files and vice versa. Existing message drafts/uploads survive.

The panel lists every ready, attached file in the current channel, including thread replies and older messages that the browser has not loaded. Each item shows a lazy image thumbnail or type icon, name, file size, uploader and share date, Preview, Download and source-message navigation. Search matches filenames literally and case-insensitively. Type filters are All, Images, PDFs, Text, Audio, Videos and Other; sorting is Newest/Oldest shared. Loading, empty, filtered-empty, retry, load-more and revoked-access states are explicit. Focus enters search on open and returns to Files on close. Escape closes the panel unless a file viewer dialog is handling it.

GET /v1/channels/:channelId/assets returns Page<ChannelFile>. ChannelFile extends AssetAttachment with preview_kind (AssetPreview.kind or file for legacy unclassified), message_id, thread_id, shared_at, uploader {id,name}. Query: q (literal filename, max255), kind (all|image|pdf|text|audio|video|other), sort (newest|oldest), limit (string1..100, default30), after (asset UUID). Rows sort by original message created_at then asset UUID; cursor lookup stays channel-scoped and preserves database timestamp precision. Pending/unattached assets never appear. Responses exclude storage keys, signed URLs and full text-preview data. Listing reads PostgreSQL only and authorizes current access on every request, even if storage is disabled. A partial index supports channel/message lookup. No new conversion/storage system or public access.

The existing attachment viewer is extracted for reuse by message cards and the file panel. Opening the viewer still fetches fresh authorized preview metadata; list rows/filmstrip use lightweight kind metadata and lazy thumbnails. Original-message navigation scrolls/focuses an already-loaded source, or opens the existing authorized SourceMessage view for older sources. Channel/session changes and access loss clear/abort private panel state; stale responses cannot repopulate it. New attachment messages refresh the open list, and a refresh control is available.

Acceptance: API/contract tests prove validation, scope, current membership, private channels, pending exclusion, thread inclusion, stable pages under timestamp ties/inserts, kind/search/sort and no storage reads. Frontend tests prove requests, pagination, filter reset, stale cancellation, errors/revocation, viewer reuse and source actions. Chat tests prove opening/closing and mutual exclusion without losing drafts. Real API/SeaweedFS and browser checks prove image/PDF previews, list filters/pagination, source navigation, downloads, focus, narrow layout and unauthorized denial.
