# Channel permissions

The user approved building the Slack flow inspected in this chat. Observed in live Slack Free: channel heading → Settings → Posting permissions → Edit, four posting audiences (everyone, everyone except guests, admins, admins plus selected people), optional replies for everyone, and broadcast-mention checkbox. Admin → Roles & permissions separately controls who can edit posting policies. Unsaved forms were cancelled. Reference screenshot: /Users/kai/.codex/visualizations/2026/11/06/01a1b12a-beee-75c0-a281-5dd045e6467e/slack-channel-permissions.jpg. Channel Manager delegation and paid-plan availability were documented at https://slack.com/help/articles/8328303095443-Understand-channel-managers-in-Slack.

Space adaptation: expose per-channel controls for every normal channel. Defaults preserve existing behavior: everyone posts/replies; workspace broadcast rules still apply; creator and joined workspace administrators manage the channel. Add up to 100 explicitly delegated non-guest channel managers. Managers can edit policies and delegation; they do not automatically gain admin-only posting rights. Specific posters must be active channel members, at most 100. Separate member-action policies for inviting, removing, editing metadata, and archiving allow full members or managers; defaults remain managers. Guests cannot manage or invite/remove members. Existing admin-only guest-assignment restrictions remain. Private channels must retain at least one eligible manager or joined workspace administrator. Legacy channels already missing one must still allow ordinary members to leave or be offboarded; this exception cannot remove an existing last manager. Removing a member clears explicit posting/management grants. Direct messages are unchanged.

Use one versioned channel_permissions row per normal channel. GET/PATCH /v1/channels/:channelId/permissions returns policy plus effective capabilities. PATCH requires the current revision; stale saves return 409. Bound all arrays and authorize both actor and selected identities. Use existing serializable transactions, conditional writes and bounded conflict retries; introduce no explicit/distributed locks. Preserve send idempotency, reject new unauthorized posts/replies/broadcasts at the shared ChatStore send boundary. Durable metadata outbox notifications refresh clients; no polling. Agent execution permissions remain their existing installation/grant model; this feature controls human user actions.

UI: Channel details About adds Managed by; Members displays manager badges; Settings adds Posting permissions plus member-action controls. Editors use shared Dialog/Button/Checkbox controls and match Slack's fields. Use effective capabilities for individual actions. Channel/thread composers retain drafts while read-only, explaining the denial; refresh permissions on channel events, focus and reconnect, and fail closed on authorization loss. Optimistic version conflicts require reloading before another save. Workspace-wide role customization beyond existing policies is a separate feature, not added here.

Verification: isolated PostgreSQL integration tests for policies, guest/outsider boundaries, stale saves, concurrent manager changes, grant cleanup, archive behavior, and shared message path. Frontend tests for dialog conditional fields, capabilities, stale errors, read-only draft preservation and live refresh. Typecheck/build, focused regressions, browser desktop/narrow inspection.
