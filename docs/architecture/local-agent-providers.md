# Local agent providers

Members can select Codex, Kiro or Claude when creating a pairing. The pairing fixes the provider, its connector ID and its skill. Existing Codex pairing requests and saved local state remain compatible. Codex uses `codex.local` / `codex.run`; Kiro uses `kiro.local` / `kiro.run`. Claude uses `claude.local` / `claude.run`.

The shared connector capability model owns enrollment, channel grants, managed sessions and broker routing. All three providers advertise persistent sessions. Each installation retains its human owner and explicit channel access. Session follow-ups preserve installation and skill; provider-specific credentials remain on the computer. Pairing and channel-grant mutations use bounded serializable transactions rather than explicit database locks. Migration036 adds pairing provider metadata; migration037 extends this through the shared connector descriptors and capabilities.

Space's connector uses a common runtime interface for invocation, readiness and shutdown. Codex retains its app-server protocol. Kiro implements ACP v3 over newline JSON-RPC with bounded buffers, request deadlines, one active turn, and coalesced response snapshots. Provider-specific state roots allow simultaneous Codex and Kiro processes. Session mappings retain their private permissions and atomic writes; the default Codex storage layout is unchanged.

Kiro credentials are managed by `kiro-cli login` inside a Space-owned HOME. The adapter does not import desktop credentials or global project configuration. By default, the generated chat-only profile has no tools, MCP servers, powers, resources or hooks. Startup checks initialization, persistent-session support and a no-inference session in the selected profile. Callbacks cannot grant filesystem, terminal or tool access. Kiro mode changes and unexpected tool events fail the turn. Client restrictions are not an OS filesystem jail.

Each new retained session mapping is saved before Space acknowledges session readiness and before inference begins. Later turns load the same session, ignoring history replay as current output. Missing storage, account changes, malformed output and uncertain transport failures fail visibly. Stop drains in-flight setup or waits for the prompt's cancellation response; a timeout stops the runtime instead of risking overlap. Kiro turns are never automatically replayed.

Setup commands and sign-in guidance are in the [connector guide](../../apps/connector/README.md#kiro). Apply migrations and restart the API and web app to use the updated provider picker. Tests exercise real PostgreSQL and Socket.IO with synthetic provider processes. Codex and Kiro have passed authenticated read-only project-tool checks; see [activity and tool verification](../real-agent-activity-qa.md).


With an explicit local `--project` directory, both adapters configure the maintained filesystem MCP server and enable its bounded file-tool allowlist. The canonical project path participates in the private session namespace. Native shell and unrelated tools remain unavailable; project configuration does not grant extra integrations. Kiro gates inference on MCP readiness and recognizes deferred project-tool discovery separately from actual calls. Its current wrapper event and the newer MCP identity envelope both map to the shared tool timeline.

Typed optional `AgentResponse.activity` carries observed working/thinking/responding/using_tools state through the existing coalesced and acknowledged snapshots. No reasoning contents are persisted. The session composer reserves the same small line used for human typing indicators, clearing activity on terminal task state. Provider failures preserve valid partial output and close uncertain in-flight runtimes. Aggregate tool detail budgeting preserves identities/statuses when many file reads exceed a snapshot's display budget.

Optional `AgentResponse.items` references messages and tools in first-appearance order by stable ID. Each payload must be referenced exactly once. Codex keeps its native message IDs; Kiro begins a new text block after a new actual tool call. Snapshots, saved history and Stop retain this order. The shared renderer groups adjacent tools while keeping intervening text in place and tool expansion stable. Older responses without references retain their existing tools-then-text presentation. Snapshot coalescing still applies; the ordered collection is not a complete lifecycle event log.

Claude uses the installed, unmodified Claude Code executable with native local sign-in. The SDK drives its local protocol. The connector launches `claude auth login/status/logout` in a private profile and retains only hashed account identity for session scoping. Migration 055 permits Claude pairings. The CLI hands each approved task to a separate SDK process with a private working directory. Managed sessions reuse their stored SDK session ID within the same Claude account and project namespace. The connector waits for Space to acknowledge session readiness before sending the prompt. It awaits process exit before releasing the turn, including on Stop. See the [Claude setup instructions](../../apps/connector/README.md#claude).
