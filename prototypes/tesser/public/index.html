Built for teams of devs and agents

Port forwarding to localhost

Every port your app uses is forwarded to your laptop, so the dev server on the machine opens at localhost:3000 like it always has. Hot reload and sign-in cookies keep working, and a panel on the page switches between branches.

Set up in less than a minute

  1. One command installs tesser, and tesser login signs you in through the browser.

    Quickstart
    ~/acme
    $ curl -fsSL https://tesser.sh/install | sh
    tesser: installing v0.48.1 (darwin-arm64)
    $ tesser login
    tesser: opening your browser to sign in
    Logged in as you@acme.dev; org Acme is now the default
    $
    $

  2. tesser skill install gives Claude Code and Codex a short skill that points them at tesser --help. From then on your agent runs the commands itself.

    Coding agents

  3. A short TOML file in the repo lists your app's ports and the install and dev commands you already use. Commit it once and every worktree can use it.

    Manifest reference

  4. Your agent runs tesser dev web in its worktree. The dev server comes up on that worktree's machine, and you open it at localhost:3000.

Flexible by design

Parallel coding agents

Every agent gets its own worktree and machine, so five agents on one repo never fight over port 3000 or your laptop's CPU.

Preview links

Put a link to your running branch in the PR. A reviewer opens it at box-7f3a91.localhost:3000 and tries the change before reading the diff.

Tests and builds

tesser exec -- pnpm test runs the suite on the worktree's machine. The output and exit code come back as if it ran locally.

Apps with a database

Each branch runs its own Postgres and Redis with Docker Compose, so one branch's migrations never touch another's data.

How Tesser compares

Most cloud dev environments ask you to move into them. Tesser fits into the workflow you already have. It syncs your checkout and runs your existing install and dev commands, with no Dockerfile or devcontainer to write.
